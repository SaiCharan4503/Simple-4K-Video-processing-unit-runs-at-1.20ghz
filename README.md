I wondered how was a Rtl describes Working of a Processor so I designed a video processing unit with the help of a Ai, I described SystemVerilog as chosen language and Described all Constraints I required 

You are a senior RTL design and verification lead with deep experience in digital video pipeline architecture, ASIC front-end design, and SystemVerilog/UVM verification. Work as a coordinated RTL and verification team, reasoning through each block as a production design would.  **Objective:** Produce an RTL-level design specification and a SystemVerilog RTL implementation for a 4K video processing unit (VPU) intended for a 1:1 sensor interface, targeting a 5nm TSMC process at 2 GHz. The unit must support frame rates of 24, 40, 90, and 120 fps at 4K resolution, and also provide simpler 1K and 2K processing modes. This is a foundational academic-style project that will later move to logic synthesis, physical design, and static timing analysis (STA), so the RTL must be written with those downstream steps in mind.  **Deliverable level:** Production-ready. Deliver synthesizable SystemVerilog RTL with a full verification plan, assertions, and coverage model, not only a basic testbench.  **Requirements to preserve:** - Support 4K processing at 24, 40, 90, and 120 fps, plus 1K and 2K modes. - Operating clock of 2 GHz; design all timing paths with this target in mind. - Process technology: 5nm TSMC; keep the RTL synthesizable and free of constructs that hinder synthesis or timing closure. - Sensor interface is 1:1 (one pixel stream mapped directly to the processing pipeline without decimation or resampling). - HDL and verification language: SystemVerilog for all RTL and testbench code.  **Deliverables to cover:** 1. Top-level block diagram and a short description of each major block (sensor interface, input buffering, processing pipeline, frame/line memory, output interface, control and configuration registers). 2. Throughput analysis showing the pixel rate per mode and fps, and whether the 2 GHz datapath width and parallelism meet each target. State the pixels-per-clock assumption explicitly and justify it. 3. Clock and reset strategy, including clock domain crossing points between the sensor and core clocks, with the synchronization approach for each crossing. 4. Memory strategy: line buffers or frame buffers, sizing for 4K, and how mode switching between 1K, 2K, and 4K is handled. 5. RTL module hierarchy with port lists for the top level and key submodules, written in synthesizable SystemVerilog. 6. Verification plan: testbench architecture (UVM, written in SystemVerilog), key directed and constrained-random scenarios per fps mode, a coverage model covering all resolution and frame-rate combinations, and SystemVerilog assertions for protocol and handshake checks. 7. Synthesis and STA readiness notes: flagged critical paths, suggested clock period constraints for 2 GHz, and guidance on pipelining and register placement to ease timing closure.  **Constraints:** - Keep the scope to a single coherent design appropriate for a basic VLSI project; do not expand into an unbounded SoC. - Flag any assumption you make (pixel format, bit depth, interface protocol such as MIPI CSI-2 or parallel) explicitly, since the user has not specified them. - Where a specification is ambiguous, choose a reasonable default and state it rather than leaving it open.
